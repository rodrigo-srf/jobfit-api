# Operations guide

This document records the operational checks used to run and troubleshoot JobFit.

## Health endpoints

- `GET /health` is a liveness check. It confirms that the web process is responding.
- `GET /ready` is a readiness check. It runs `SELECT 1` against the configured database.

Render uses `/health` so a temporary database interruption does not continuously restart an otherwise healthy web process. Use `/ready` when validating a deployment end to end.

## Request tracing

Every response includes:

- `X-Request-ID`, accepted from the caller or generated by the API;
- `X-Response-Time-Ms`, the server-side request duration.

Application logs record the method, path, status, duration and request ID. Query strings, authorization headers and response bodies are deliberately excluded to avoid leaking credentials or personal data.

## Local stack

Copy the example configuration and replace the development secret:

```bash
cp .env.example .env
docker compose up --build
```

The API waits for PostgreSQL to pass `pg_isready`. Verify both endpoints after startup:

```bash
curl http://localhost:8000/health
curl http://localhost:8000/ready
```

## CI checks

Pull requests and pushes to `main` run:

1. Python dependency installation;
2. bytecode compilation;
3. the pytest suite;
4. dependency vulnerability auditing with `pip-audit`;
5. a clean production-container build.

Dependabot checks Python, GitHub Actions and Docker dependencies weekly.

## Deployment checks

After a Render deployment:

1. confirm the deployment is healthy in the Render dashboard;
2. call `/health` and `/ready`;
3. open `/docs` and the dashboard;
4. inspect logs for unexpected `request_failed` entries;
5. run a small authenticated smoke test when a change affects persistence or authentication.

## Rollback

If a deployment fails, use Render's deployment history to redeploy the last known-good commit. Do not change production database credentials during an application rollback. Database schema changes require a separate migration and rollback plan.
